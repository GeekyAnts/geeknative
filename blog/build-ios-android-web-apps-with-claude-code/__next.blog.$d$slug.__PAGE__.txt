This post walks through how a geeknative project sets that up.</p>
<h2 id="1-create-the-project">1. Create the project<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#1-create-the-project">#</a></h2>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="shell"><code><span class="line"><span style="color:#0B0B0B;font-weight:bold">npm</span><span style="color:#0B0B0B"> create</span><span style="color:#0B0B0B"> geeknative@latest</span><span style="color:#0B0B0B"> habits</span><span style="color:#686664"> --</span><span style="color:#686664"> --name</span><span style="color:#9F0310"> "Habits"</span><span style="color:#686664"> --id</span><span style="color:#0B0B0B"> com.acme.habits</span></span>
<span class="line"><span style="color:#0B0B0B;font-weight:bold">cd</span><span style="color:#0B0B0B"> habits</span></span>
<span class="line"><span style="color:#0B0B0B;font-weight:bold">make</span><span style="color:#0B0B0B"> doctor</span></span></code></pre>
<p><code>make doctor</code> checks Node, the contracts, Xcode and an iPhone simulator, Java and the Android SDK. <code>make doctor FIX=1</code> installs what it safely can. Then build and test the starter app on all three platforms:</p>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="shell"><code><span class="line"><span style="color:#0B0B0B;font-weight:bold">make</span><span style="color:#0B0B0B"> check</span></span></code></pre>
<p>The starter has two screens, Home and Settings, built the same way on iOS, Android and the web. They are the pattern new features follow.</p>
<h2 id="2-open-it-in-claude-code">2. Open it in Claude Code<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#2-open-it-in-claude-code">#</a></h2>
<p>Start Claude Code in the project root. The root CLAUDE.md is one line, <code>@AGENTS.md</code>, so Claude loads the same instructions every agent follows. Each app folder has its own AGENTS.md and CLAUDE.md, which load when Claude works on files there.</p>
<p>Claude Code also gets a few extras in <code>.claude/</code>:</p>
<ul>
<li>Three subagents: <code>ios-engineer</code>, <code>android-engineer</code> and <code>web-engineer</code>.</li>
<li>A hook that runs <code>geeknative gen</code> whenever a file in <code>contracts/</code> changes.</li>
<li>A stop hook that asks once if a turn changed some apps but not the others.</li>
</ul>
<h2 id="3-describe-the-whole-app">3. Describe the whole app<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#3-describe-the-whole-app">#</a></h2>
<p>The first prompt should describe the product:</p>
<blockquote>
<p>Build a habit tracker. People create habits, check them off each day, and see their current streak.</p>
</blockquote>
<p>Claude treats this as a product request and follows the product playbook. It fills in PRODUCT.md, sets the design direction, plans the screens in <code>spec/navigation.md</code>, and writes one spec per feature, each with numbered acceptance criteria like <code>AC-habits-1</code>.</p>
<h2 id="4-watch-the-three-apps-get-built">4. Watch the three apps get built<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#4-watch-the-three-apps-get-built">#</a></h2>
<p>For each feature, Claude stays the lead. It owns the spec and the contracts, and hands the platform work to the three subagents in parallel. Each subagent:</p>
<ol>
<li>reads the spec and follows the Settings feature as the pattern;</li>
<li>implements from the spec, without porting code from the other apps;</li>
<li>names its tests after the acceptance criteria;</li>
<li>runs its platform's check (<code>make check-ios</code>, <code>make check-android</code> or <code>make check-web</code>) until it passes;</li>
<li>reports the files it changed and the criteria it covered.</li>
</ol>
<p>Features are built in vertical slices. The first feature goes through all three apps before the next one starts, so the apps stay in step at every point.</p>

<p>Run the apps with <code>make run-ios</code>, <code>make run-android</code> and <code>make run-web</code>.</p>
<h2 id="6-keep-talking-normally">6. Keep talking normally<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#6-keep-talking-normally">#</a></h2>
<p>From here, you prompt the way you would in any project. "Make it feel warmer, with rounder corners" is a design request: Claude updates DESIGN.md and <code>contracts/tokens.json</code>, and the hook regenerates code for every app. "Add reminders" is a feature request: a new spec, then three implementations. "The streak resets at the wrong time on Android" is a bug: Claude checks whether the spec covered the case, fixes the spec if it didn't, fixes every app that doesn't match, and adds a regression test named after the criterion.</p>
<h2 id="not-using-claude-code">Not using Claude Code?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#not-using-claude-code">#</a></h2>
<p>The same project works with Codex, Cursor, Gemini CLI, the GitHub Copilot coding agent and any agent that reads AGENTS.md. Claude Code just gets the subagents and hooks on top.
