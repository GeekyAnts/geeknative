Ask it for a notes list on iOS and it writes one. Ask again for Android a week later and you get a slightly different notes list. The names differ, the empty state differs, the copy differs. Nothing is wrong, exactly. It's just not the same product.</p>
<p>The fix is not a better prompt. It is a place for decisions to live that isn't the code.</p>
<h2 id="decisions-belong-in-files">Decisions belong in files<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#decisions-belong-in-files">#</a></h2>
<p>In a geeknative project, every kind of decision has a home:</p>

</tr>
<tr>

<td>DESIGN.md and <code>contracts/tokens.json</code></td>
</tr>
<tr>

<td><code>spec/navigation.md</code></td>

</tr>

<p>The agent reads these before it writes code, and updates them before it changes behavior. A later request, on any platform, starts from the same decisions.</p>
<h2 id="triage-first">Triage first<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#triage-first">#</a></h2>
<p>Not every request is the same kind of work. AGENTS.md has the agent classify each one before acting: product, feature, design, copy, bug, platform-specific, engineering or a question. The main types have a playbook in <code>.geeknative/playbooks/</code> that says which files change first.</p>
<p>"Make it feel warmer" is a design request, so DESIGN.md and the tokens change, not individual screens. "Change the button label" is copy, so <code>contracts/strings/</code> changes, and every app picks it up from <code>make gen</code>. This one step removes most drift.</p>
<h2 id="contracts-the-compiler-enforces">Contracts the compiler enforces<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#contracts-the-compiler-enforces">#</a></h2>
<p>Some decisions are too important to leave to reading. App identity, design tokens, strings and icons are JSON contracts compiled into code for each platform. If a contract is invalid, <code>make gen</code> fails with the file and field. If generated files are out of date, <code>make check</code> fails. The agent can't quietly hard-code a color or a string that drifts.</p>
<h2 id="a-definition-of-done">A definition of done<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#a-definition-of-done">#</a></h2>
<p>The last piece is verification. A change is done when:</p>
<ol>
<li>the source of truth is updated;</li>
<li>every affected app builds and passes <code>make check</code>;</li>
<li>tests name the acceptance criteria they cover;</li>
<li>each platform's status is recorded in the spec;</li>
<li>the agent reports one line per platform.</li>
</ol>
<h2 id="works-with-any-agent">Works with any agent<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#works-with-any-agent">#</a></h2>
<p>All of this is plain files: Markdown instructions, JSON contracts, a Makefile and a small CLI. It follows the AGENTS.md convention, so Claude Code, Codex, Cursor, Gemini CLI and the GitHub Copilot coding agent all pick it up. Nothing is installed into the agent.</p>
