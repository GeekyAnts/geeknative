They differ in who draws the screen.</p>
<p>Flutter draws its own UI. You write widgets in Dart, and Flutter's rendering engine paints them on every platform, so the app looks the same everywhere. It includes Material and Cupertino widget sets that follow each platform's design.</p>
<p>geeknative uses each platform's own toolkit. The iOS app is SwiftUI, the Android app is Jetpack Compose, and the web app is React. A coding agent builds all three from one spec, and shared contracts keep the brand, copy and behavior the same.</p>

<h2 id="choose-flutter-when">Choose Flutter when<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#choose-flutter-when">#</a></h2>
<ul>
<li>You want a pixel-identical, highly custom UI on every platform, like a game-like or illustration-heavy app.</li>
<li>You need desktop apps from the same codebase.</li>
<li>Your team knows Dart, or is happy to learn one language for everything.</li>
<li>You want one codebase and its ecosystem of packages.</li>
</ul>
<h2 id="choose-geeknative-when">Choose geeknative when<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#choose-geeknative-when">#</a></h2>
<ul>
<li>You want apps that look and behave like their platform: iOS navigation, Material 3, platform text fields, sheets and gestures.</li>
<li>Accessibility features like VoiceOver, TalkBack and Dynamic Type should come from the platform's own components.</li>
<li>The web app should be a normal React app that your web team can work on and search engines can index like any site.</li>
<li>You build with coding agents and want them to follow a spec with checks on every platform.</li>
</ul>
<h2 id="the-web-is-a-different-story">The web is a different story<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-web-is-a-different-story">#</a></h2>
<p>Flutter's web output is rendered by its engine, which suits app-like experiences. geeknative's web app is React on TanStack Start with Tailwind CSS, built from the same spec as the mobile apps. If the web is a core channel for you, that difference matters.</p>
<h2 id="questions">Questions<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#questions">#</a></h2>
<h3 id="does-geeknative-make-the-apps-look-the-same">Does geeknative make the apps look the same?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#does-geeknative-make-the-apps-look-the-same">#</a></h3>
<p>They look like one brand, not identical. Colors, type, spacing and radii come from <code>contracts/tokens.json</code> and reach every app. Components and navigation follow each platform. See <a href="/geeknative/docs/guides/design-changes/">Design changes</a>.</p>
<h3 id="is-three-codebases-more-to-maintain">Is three codebases more to maintain?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#is-three-codebases-more-to-maintain">#</a></h3>
<p>There is more code, but your agent writes it, and you maintain one spec. <code>make check</code> builds and tests all three apps, and <code>make parity</code> shows gaps. See <a href="/geeknative/docs/concepts/specs-and-parity/">Specs and parity</a>.</p>
