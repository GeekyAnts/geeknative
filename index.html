01The idea

Cross-platform apps, without cross-platform technology.

Cross-platform apps, without cross-platform technology.

One spec.

Three native codebases.

Your agent keeps them in step.

Cross-platform frameworks trade native feel for shared code. geeknative keeps the native code and shares everything else: the product spec, the design tokens, the copy and the tests. The agent writes SwiftUI for iOS, Compose for Android and React for the web, and the shared contracts keep the three apps the same product.

03How it works

A prompt becomes a spec. A spec becomes three apps.

AGENTS.md teaches any coding agent the same loop: work out what you asked for, write it down once, then build it natively three times and prove it.

Fig. 03.1 · The loop, carried by the colony

The loop

Every request, every time.

  1. 01

    Update the source of truth

    The spec, PRODUCT.md, DESIGN.md or a contract changes first, so every app builds against the same description.

  2. 02

    Regenerate

    make gen compiles the contracts into Swift, Kotlin, Android resources and TypeScript. Nobody edits generated code.

  3. 03

    Build on each platform

    Each app follows its own AGENTS.md. Agents that support sub-agents build the three apps in parallel.

  4. 04

    Verify

    make check builds and tests every app. The agent keeps going until all three pass.

  5. 05

    Record and report

    Each platform's status goes into the spec, make parity updates the coverage table, and the agent reports one line per platform.

Fig. 03.2 · One request, traced through the repoRead how it works

04Triage

Just talk. The agent sorts it out.

No commands to learn. The agent states how it read your request in one line before it touches anything, so you can correct it early:

Feature: notes list → spec/features/notes.md, strings · iOS, Android, Web

  • 01Product

    “Build a habit tracker for runners.”

    PRODUCT.md, DESIGN.md, navigation, feature specs

  • 02Feature

    “Add a notes list where I can add and delete notes.”

    A new spec/features/notes.md

  • 03Behavior

    “Sort notes by date instead.”

    That feature's spec

  • 04Design

    “Make it feel warmer, with rounder corners.”

    DESIGN.md and contracts/tokens.json

  • 05Copy

    “Rename Save to Done.”

    contracts/strings, then make gen

  • 06Bug

    “Deleting the last note crashes.”

    The spec, only if it was silent or wrong

  • 07Platform-specific

    “On iPhone, add a haptic when deleting.”

    The spec's Platform notes; iOS only

  • 08Engineering

    “Upgrade Compose to the latest BOM.”

    Nothing in the spec

  • 09Question

    “Why does Android use radio buttons here?”

    Nothing: the agent answers

05Contracts

Write it once. Compile it three ways.

App identity, design tokens, copy and icons live in contracts/. make gen turns them into code for each app, so a color, a string or a version number can't drift.

Fig. 05 · make gen writes these. Nobody edits them by hand, and make check fails if they drift.

06Parity

Tests carry the spec. Parity is a table, not a hope.

Specs number their acceptance criteria. Each app's tests name the criteria they cover, and make parity turns that into a table. Gaps show up before users find them.

Fig. 06 · The starter app's acceptance criteria, as make parity reports them

07Agents

Bring the agent you already use.

geeknative is plain files in your repo. The instructions follow the AGENTS.md convention, and Claude Code gets extra wiring on top.

  • Claude CodeReads AGENTS.md through one-line CLAUDE.md imports. ios-engineer, android-engineer and web-engineer subagents build in parallel. Hooks regenerate code when a contract changes, and flag a turn that changed only some of the apps.Subagents + hooks
  • CodexReads AGENTS.md at the root and in each app, and runs the same make targets.AGENTS.md
  • CursorPicks up the root and per-app AGENTS.md files as project rules.AGENTS.md
  • GitHub CopilotThe coding agent follows AGENTS.md in pull requests it opens.AGENTS.md
  • Gemini CLIThe project setting points Gemini CLI at AGENTS.md instead of GEMINI.md..gemini/settings.json
  • Your agentMarkdown instructions, a Makefile, and a CLI with short output and full logs. Nothing to install into the agent.Plain files
