<h2 id="cross-platform-apps-without-cross-platform-technology">Cross-platform apps without cross-platform technology<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#cross-platform-apps-without-cross-platform-technology">#</a></h2>
<p>Native apps use each platform's own language, UI toolkit and conventions. They look and behave the way people on that platform expect, and they get new platform features first. The cost has always been building everything three times and keeping three codebases in step.</p>
<p>Coding agents make writing three implementations cheap. What's still hard is keeping them consistent: the same features, the same behavior, the same copy and the same brand. geeknative gives the agent the structure to do that:</p>
<ul>
<li><strong>A shared source of truth.</strong> PRODUCT.md, DESIGN.md and one spec per feature, with numbered acceptance criteria.</li>
<li><strong>Contracts compiled into every app.</strong> The app identity, design tokens, copy and icon names live in <code>contracts/</code>, and <code>make gen</code> generates the matching Swift, Kotlin, Android resources, TypeScript and Tailwind theme.</li>
<li><strong>The same architecture with the same names.</strong> A feature called <code>notes</code> is <code>NotesScreen</code>, <code>NotesViewModel</code> and <code>NotesRepository</code> in every app.</li>
<li><strong>Checks for every app.</strong> <code>make check</code> builds and tests all three, and <code>make parity</code> shows which acceptance criteria each platform covers.</li>
</ul>

<p>Each app starts with the same two screens, Home and Settings, built the same way on all three platforms. They're a working reference for the patterns new features follow, and you can replace them freely.</p>
<h2 id="what-it-isnt">What it isn't<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#what-it-isnt">#</a></h2>
<ul>
<li><strong>Not a runtime.</strong> There's no shared code and no cross-platform layer. Each app is plain SwiftUI, Compose or React.</li>
<li><strong>Not a UI kit.</strong> Each app uses its platform's own components. Design tokens make them look like one brand.</li>
<li><strong>Not tied to a backend.</strong> Features read and write through repository interfaces with local implementations. A backend can be added later without changing screens.</li>
<li><strong>Not tied to one agent.</strong> Any agent that reads AGENTS.md works. Claude Code gets extra integration.</li>
</ul>
