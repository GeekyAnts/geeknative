<h2 id="how-the-cli-finds-your-tools">How the CLI finds your tools<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#how-the-cli-finds-your-tools">#</a></h2>
<p><strong>Android SDK.</strong> <code>make doctor</code> and <code>make check-android</code> look in this order: <code>apps/android/local.properties</code>, <code>ANDROID_HOME</code>, <code>ANDROID_SDK_ROOT</code>, <code>~/Library/Android/sdk</code>, <code>/opt/homebrew/share/android-commandlinetools</code>, <code>/usr/local/share/android-commandlinetools</code>, and <code>~/Android/Sdk</code>. When they find it, they write <code>apps/android/local.properties</code> (git-ignored) so Gradle uses it too.</p>
<p><strong>iOS simulator.</strong> The CLI builds and tests on the simulator named in the <code>GEEKNATIVE_IOS_SIMULATOR</code> environment variable (a name or UDID), if set. Otherwise it uses a booted iPhone simulator, or an iPhone on the newest installed iOS runtime.</p>
