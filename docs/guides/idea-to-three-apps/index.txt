21:Te4a,<p>The first prompt in a new project usually describes the app. The agent treats it as a <strong>Product</strong> request and follows <code>.geeknative/playbooks/product.md</code>.</p>
<blockquote>
<p>Build a habit tracker. People create habits, check them off each day, and see their current streak.</p>
</blockquote>
<h2 id="what-the-agent-does">What the agent does<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#what-the-agent-does">#</a></h2>
<ol>
<li><strong>Understands the product.</strong> It restates the product in one sentence. It asks only about things that would change the data model or the navigation structure, and assumes the rest.</li>
<li><strong>Fills in PRODUCT.md.</strong> The one-sentence description, the audience, the feature list, the glossary and what's out of scope. Glossary terms become the names used in code on every platform, so a "Habit" is <code>Habit</code> in Swift, Kotlin and TypeScript.</li>
<li><strong>Sets the design direction.</strong> If you described a look, it writes the direction in DESIGN.md and updates <code>contracts/tokens.json</code> (colors in light and dark, type, spacing and radii), then runs <code>make gen</code>.</li>
<li><strong>Plans navigation.</strong> It updates <code>spec/navigation.md</code> with the screens and how people move between them: tabs, stacks and modals. The starter Settings screen stays unless you say otherwise.</li>
<li><strong>Writes feature specs.</strong> One spec per feature in <code>spec/features/</code>, from <code>.geeknative/templates/feature.md</code>, with every platform's status set to <code>planned</code>. The first version is kept small: the core loop first.</li>
<li><strong>Builds in vertical slices.</strong> It takes the first feature through the whole loop on all three apps (spec, contracts, implementation, checks, status), then starts the next. It never builds every screen on one platform first.</li>
<li><strong>Replaces the starter content.</strong> Once real features exist, it updates or removes Home's welcome card and updates <code>spec/features/home.md</code> to match.</li>
<li><strong>Reports</strong> what it built on each platform, what's planned next, and the assumptions it made.</li>
</ol>
<h2 id="why-vertical-slices">Why vertical slices<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#why-vertical-slices">#</a></h2>
<p>Building one feature across all three platforms before starting the next keeps the apps in step at every point. If the second platform reveals a gap in the spec, only one feature needs rechecking, not a whole app.</p>
