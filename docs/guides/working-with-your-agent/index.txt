<h2 id="every-request-is-for-all-three-apps">Every request is for all three apps<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#every-request-is-for-all-three-apps">#</a></h2>
<p>Unless you name a platform ("on Android, ...") or the spec marks something as platform-only, a request is done only when iOS, Android and web all do it.</p>
<h2 id="the-agent-triages-first-out-loud">The agent triages first, out loud<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-agent-triages-first-out-loud">#</a></h2>
<p>Before changing anything, the agent decides what kind of request it is and says so in the first line of its reply:</p>
<blockquote>
<p><strong>Feature:</strong> notes list → spec/features/notes.md, strings · iOS, Android, Web</p>
</blockquote>
<p>If it read you wrong, correct it before any work happens.</p>

<h2 id="plan-before-building">Plan before building<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#plan-before-building">#</a></h2>
<p>Say "plan", "spec only" or "don't build yet" and the agent stops after updating the docs. Review the spec, then ask it to build.</p>
<h2 id="when-the-agent-asks-and-when-it-assumes">When the agent asks, and when it assumes<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#when-the-agent-asks-and-when-it-assumes">#</a></h2>
<p>The agent asks only when a wrong guess would be expensive to undo: the data model, the navigation structure, deleting features or data, or anything irreversible. Otherwise it picks the conventional option, notes it under "Assumptions" in the spec (and in <code>spec/decisions.md</code> if it affects more than one feature), and mentions it in its report.</p>
<h2 id="what-done-means">What "done" means<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#what-done-means">#</a></h2>
<p>The agent finishes when:</p>
<ul>
<li>the docs and contracts describe the new behavior;</li>
<li><code>make gen</code> leaves no changes;</li>
<li>checks pass for every platform it touched;</li>
<li>each platform's status is recorded in the feature's front matter and <code>spec/parity.md</code> is current;</li>
<li>anything left undone is in its report, with the reason.</li>
</ul>
<p>Its report has one line per platform (done, partial or skipped, and why), the checks it ran, and the assumptions it made.</p>
<h2 id="tips">Tips<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#tips">#</a></h2>
<ul>
<li><strong>One feature at a time.</strong> The agent finishes a feature on every platform before starting the next. Big asks work best as a sequence of features.</li>
<li><strong>Review the spec diff.</strong> It's the shortest description of what changed in three codebases.</li>
<li><strong>Name a platform only when you mean it.</strong> "On Android" makes a change Android-only.</li>
<li><strong>Ask questions freely.</strong> Questions never change files.</li>
