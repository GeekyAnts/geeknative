<h2 id="direction-first">Direction first<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#direction-first">#</a></h2>
<p>For a broad request ("warmer", "more premium", "calmer"), the agent first updates the Direction section of DESIGN.md in a sentence or two. Later changes stay consistent with it.</p>
<h2 id="roles-not-hues">Roles, not hues<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#roles-not-hues">#</a></h2>
<p>New colors are named by purpose (<code>success</code>, <code>warning</code>), not by hue (<code>green</code>). That keeps the meaning stable when the palette changes, and every app gets the new color on the next <code>make gen</code>.</p>

<h2 id="stay-native">Stay native<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#stay-native">#</a></h2>
<p>Brand elements (color, type, spacing, imagery) change everywhere. Platform conventions stay native unless you explicitly ask otherwise: navigation bars, system controls, gestures and sheets. DESIGN.md's "Same everywhere, native where it counts" table lists which is which.</p>
<h2 id="type-and-fonts">Type and fonts<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#type-and-fonts">#</a></h2>
<p>Typography tokens are roles: <code>display</code>, <code>headline</code>, <code>title</code>, <code>body</code>, <code>label</code> and <code>caption</code>. On iOS each maps to a Dynamic Type style, so it follows the user's text size. On Android sizes are in sp and on web in rem, so they scale with the user's font size setting. Each token says which iOS style and which Material 3 type style it maps to; see the <a href="/geeknative/docs/reference/contracts/#tokensjson">contracts reference</a>.</p>
<p>The apps use each platform's system font. Custom fonts aren't supported by codegen yet; they're on the <a href="/geeknative/docs/project/roadmap/">roadmap</a>.</p>
