<h2 id="the-loop">The loop<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-loop">#</a></h2>
<p>Every change follows the same steps, from AGENTS.md:</p>
<ol>
<li><strong>Update the source of truth</strong>: the spec, DESIGN.md, PRODUCT.md or a contract.</li>
<li><strong>Regenerate</strong> with <code>make gen</code> if contracts changed.</li>
<li><strong>Implement on each platform</strong>, reading <code>apps/&#x3C;platform>/AGENTS.md</code> first. Agents with sub-agents give each platform its own; only the lead edits <code>spec/</code>, <code>contracts/</code>, PRODUCT.md and DESIGN.md.</li>
<li><strong>Verify</strong> with <code>make check-ios</code>, <code>make check-android</code> and <code>make check-web</code>, or <code>make check</code> for everything, and fix until they pass.</li>
<li><strong>Record</strong> each platform's status in the feature's front matter, then run <code>make parity</code>.</li>
<li><strong>Report</strong> one line per platform, the checks run, and the assumptions made.</li>
</ol>
<h2 id="keeping-the-apps-aligned">Keeping the apps aligned<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#keeping-the-apps-aligned">#</a></h2>
<ul>
<li><strong>Build from the spec, not by porting.</strong> If the agent had to read another app's code to know how something should behave, the spec has a gap, and the spec gets fixed first.</li>
<li><strong>Same IDs everywhere.</strong> Test IDs (<code>notes.addButton</code>), storage keys and stored values match across apps.</li>
<li><strong>Tests name acceptance criteria.</strong> The ID (for example <code>AC-notes-2</code>) goes in each test's name, so <code>make parity</code> can show coverage.</li>
<li><strong>Native, not identical.</strong> Features, flows, data, copy and brand match. Navigation chrome, controls, gestures and system conventions follow each platform.</li>
<li><strong>One feature at a time.</strong> A feature is finished on every platform before the next one starts.</li>
<li><strong>Spec changes ripple.</strong> If building one platform changes the spec, the platforms already done get rechecked.</li>
</ul>
<h2 id="done-means">Done means<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#done-means">#</a></h2>
<ul>
<li>The docs and contracts describe the new behavior.</li>
<li><code>make gen</code> leaves no changes.</li>
<li>Checks pass for every platform touched.</li>
<li>Each platform's status is recorded and <code>spec/parity.md</code> is current.</li>
<li>Anything left undone is in the report, with the reason.</li>
