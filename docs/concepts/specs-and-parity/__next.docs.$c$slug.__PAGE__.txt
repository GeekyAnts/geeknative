<h2 id="acceptance-criteria">Acceptance criteria<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#acceptance-criteria">#</a></h2>
<p>Criteria are testable and platform-neutral, and numbered <code>AC-&#x3C;feature-id>-&#x3C;n></code>. Every platform's tests put the ID in the test name:</p>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="swift"><code><span class="line"><span style="color:#686664">@</span><span style="color:#CA0515">Test</span><span style="color:#686664">(</span><span style="color:#9F0310">"AC-settings-1: appearance defaults to System"</span><span style="color:#686664">)</span></span></code></pre>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="kotlin"><code><span class="line"><span style="color:#0B0B0B">@Test</span></span>
<span class="line"><span style="color:#CA0515">fun</span><span style="color:#0B0B0B;font-weight:bold"> `AC-settings-1 appearance defaults to System`</span><span style="color:#0B0B0B">() </span><span style="color:#686664">=</span><span style="color:#0B0B0B;font-weight:bold"> runTest</span><span style="color:#0B0B0B"> { </span><span style="color:#686664">..</span><span style="color:#0B0B0B">. }</span></span></code></pre>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="ts"><code><span class="line"><span style="color:#0B0B0B;font-weight:bold">test</span><span style="color:#686664">(</span><span style="color:#9F0310">'AC-settings-1: appearance defaults to System'</span><span style="color:#686664">,</span><span style="color:#CA0515"> async</span><span style="color:#686664"> ()</span><span style="color:#CA0515"> =></span><span style="color:#686664"> {</span><span style="color:#686664"> ...</span><span style="color:#686664"> })</span></span></code></pre>
<p>Mark a criterion <code>(ui)</code> when it's about what the user sees or taps:</p>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="markdown"><code><span class="line"><span style="color:#686664">-</span><span style="color:#0B0B0B"> AC-home-3 (ui): Home has an entry point that opens Settings.</span></span></code></pre>
<p>Only a test that drives the real UI covers a <code>(ui)</code> criterion: an XCUITest in <code>apps/ios/AppUITests</code> (put the ID in <code>XCTContext.runActivity(named:)</code>), a Compose UI test on Android (a file that creates a compose rule, run on Robolectric), or a web test that renders into a DOM (<code>// @vitest-environment happy-dom</code> with <code>createRoot</code>, <code>hydrateRoot</code> or <code>render</code>). A test that checks a view model or a route names the criterion but doesn't cover it.</p>
<h2 id="make-parity">make parity<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#make-parity">#</a></h2>
<p><code>make parity</code> reads every spec in <code>spec/features/</code> (files starting with <code>_</code> are skipped), collects the criteria from list items that start with an <code>AC-</code> ID, and searches each app's tests for those IDs:</p>
<div class="table-wrap"><table>
<thead>
<tr>
<th>App</th>
<th>Test files searched</th>
</tr>
</thead>
<tbody>
<tr>
<td>iOS</td>
<td>Swift files in <code>apps/ios/*Tests/</code></td>
</tr>
<tr>
<td>Android</td>
<td>Kotlin files in <code>apps/android/app/src/test/</code> and <code>src/androidTest/</code></td>
</tr>
<tr>
<td>Web</td>
<td><code>*.test.ts(x)</code> and <code>*.spec.ts(x)</code> files in <code>apps/web/src/</code>, and <code>apps/web/e2e/</code></td>
</tr>
</tbody>
</table></div>
<p>It writes <code>spec/parity.md</code> and prints the gaps. A gap is a criterion no test names, or a <code>(ui)</code> criterion only non-UI tests name:</p>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="text"><code><span class="line"><span>! cart       iOS done 6/7 · Android done 7/7 · Web done 7/7</span></span>
<span class="line"><span>             AC-cart-5 needs a UI test on iOS (only other tests name it)</span></span>
<span class="line"><span>✔ settings   iOS done 4/4 · Android done 4/4 · Web done 4/4</span></span>
<span class="line"><span>Wrote spec/parity.md</span></span></code></pre>
<p><code>spec/parity.md</code> starts with a <strong>Consistency:</strong> line (<code>strict</code> or <code>adapted</code>) from <code>contracts/app.json</code>, then a summary table and a per-criterion table:</p>
<div class="table-wrap"><table>
<thead>
<tr>
<th>Feature</th>
<th>iOS</th>
<th>Android</th>
<th>Web</th>
</tr>
</thead>
<tbody>
<tr>
<td>Home</td>
<td>✅ done · 3/3 tested</td>
<td>✅ done · 3/3 tested</td>
<td>✅ done · 3/3 tested</td>
</tr>
<tr>
<td>Settings</td>
<td>✅ done · 4/4 tested</td>
<td>✅ done · 4/4 tested</td>
<td>✅ done · 4/4 tested</td>
</tr>
</tbody>
</table></div>
