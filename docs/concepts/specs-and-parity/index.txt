<h2 id="acceptance-criteria">Acceptance criteria<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#acceptance-criteria">#</a></h2>

<h2 id="make-parity">make parity<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#make-parity">#</a></h2>
<p><code>make parity</code> reads every spec in <code>spec/features/</code> (files starting with <code>_</code> are skipped), collects the criteria from list items that start with an <code>AC-</code> ID, and searches each app's tests for those IDs:</p>
<div class="table-wrap"><table>
<thead>
<tr>
<th>App</th>
<th>Test files searched</th>
</tr>
</thead>
<tbody>
<tr>
<td>iOS</td>
<td>Swift files in <code>apps/ios/*Tests/</code></td>
</tr>
<tr>
<td>Android</td>
<td>Kotlin files in <code>apps/android/app/src/test/</code> and <code>src/androidTest/</code></td>
</tr>
<tr>
<td>Web</td>
<td><code>*.test.ts(x)</code> and <code>*.spec.ts(x)</code> files in <code>apps/web/src/</code>, and <code>apps/web/e2e/</code></td>
</tr>
</tbody>
</table></div>
<p>It writes <code>spec/parity.md</code> and prints the gaps. For the starter app it reports:</p>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="text"><code><span class="line"><span>! home       iOS done 0/3 · Android done 0/3 · Web done 2/3</span></span>
<span class="line"><span>             AC-home-1 untested on iOS</span></span>
<span class="line"><span>             ...</span></span>
<span class="line"><span>✔ settings   iOS done 4/4 · Android done 4/4 · Web done 4/4</span></span>
<span class="line"><span>Wrote spec/parity.md</span></span></code></pre>
