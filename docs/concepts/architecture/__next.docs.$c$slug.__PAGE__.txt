<h2 id="dependencies-a-hand-written-appcontainer">Dependencies: a hand-written AppContainer<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#dependencies-a-hand-written-appcontainer">#</a></h2>
<p>Every app wires its dependencies by hand in an <code>AppContainer</code>, with no dependency injection framework.</p>
<ul>
<li><strong>iOS:</strong> <code>AppContainer.live()</code> at launch, put in the SwiftUI environment. <code>AppContainer.preview()</code> uses in-memory repositories for previews and tests.</li>
<li><strong>Android:</strong> <code>AppContainer.live(context)</code> in the <code>Application</code> class, provided to composables through <code>LocalAppContainer</code>. ViewModels are created with <code>viewModel { SettingsViewModel(container.settingsRepository) }</code>. <code>AppContainer.preview()</code> is for previews and tests.</li>
<li><strong>Web:</strong> <code>createAppContainer()</code> in <code>router.tsx</code>, passed to every route through router context with the TanStack Query client.</li>
</ul>
<p>The same idea appears in all three apps, and Gradle builds stay free of annotation processing.</p>
<h2 id="no-backend-yet">No backend yet<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#no-backend-yet">#</a></h2>
<p>Features read and write through repository interfaces with local implementations: UserDefaults on iOS, DataStore on Android, localStorage on web. When a backend arrives, new repository implementations call it, and <code>AppContainer</code> swaps them in. Screens and view models don't change.</p>
<p>On the web, TanStack Start's server functions and API routes are only for web-only concerns (rendering, cookies, SEO). Logic the mobile apps need too goes through repositories, so a future backend can serve all three apps.</p>
