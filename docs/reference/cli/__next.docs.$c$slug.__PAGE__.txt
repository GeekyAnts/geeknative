3:T329e,<p>The <code>geeknative</code> CLI is a dev dependency of every project. Inside a project you normally use it through <code>make</code>. Run it directly with <code>npx geeknative &#x3C;command></code>.</p>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="text"><code><span class="line"><span>geeknative &#x3C;command></span></span>
<span class="line"><span></span></span>
<span class="line"><span>  create &#x3C;folder>      Create a project. Options: --name "My App" --id com.acme.myapp --no-install --no-git</span></span>
<span class="line"><span>  gen                  Regenerate platform code from contracts/</span></span>
<span class="line"><span>  check [targets]      Verify contracts, then build and test. Targets: all (default), contracts, ios, android, web</span></span>
<span class="line"><span>  doctor [--fix]       Check Xcode, the Android SDK and Node; --fix installs what it can</span></span>
<span class="line"><span>  parity               Update spec/parity.md from feature specs and tests</span></span>
<span class="line"><span>  run &#x3C;platform>       Build and launch: ios (simulator), android (emulator or device), web (dev server)</span></span>
<span class="line"><span>  version              Print the version</span></span></code></pre>
<p><code>geeknative help</code> (or <code>-h</code>) prints this list, and <code>-v</code> prints the version. Every command except <code>create</code> and <code>version</code> works from anywhere inside a project: it walks up from the current folder to the one containing <code>contracts/app.json</code>.</p>
<h2 id="create">create<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#create">#</a></h2>

<p><code>create</code>:</p>
<ol>
<li>checks that the folder doesn't exist or is empty, and that the name and ID are valid on every platform;</li>
<li>copies the template;</li>
<li>writes the name and ID to <code>contracts/app.json</code> and the folder name to <code>package.json</code>;</li>
<li>runs <code>gen</code> and writes <code>.geeknative/lock.json</code>;</li>
<li>writes <code>apps/android/local.properties</code> if it finds an Android SDK;</li>
<li>runs <code>npm install</code>, then <code>git init</code> and a first commit (unless you passed <code>--no-install</code> or <code>--no-git</code>).</li>
</ol>
<h2 id="gen">gen<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#gen">#</a></h2>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="shell"><code><span class="line"><span style="color:#0B0B0B;font-weight:bold">npx</span><span style="color:#0B0B0B"> geeknative</span><span style="color:#0B0B0B"> gen</span><span style="color:#A3A09C;font-style:italic">        # or: make gen</span></span></code></pre>
<p>Validates every contract, writes the generated files that changed, and deletes generated files that are no longer produced (for example, after removing a locale). It lists the files it changed. Invalid contracts fail with a message naming the file and field. See <a href="/geeknative/docs/reference/contracts/">Contracts</a>.</p>
<h2 id="check">check<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#check">#</a></h2>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="shell"><code><span class="line"><span style="color:#0B0B0B;font-weight:bold">npx</span><span style="color:#0B0B0B"> geeknative</span><span style="color:#0B0B0B"> check</span><span style="color:#0B0B0B"> [all </span><span style="color:#686664">|</span><span style="color:#0B0B0B;font-weight:bold"> contracts</span><span style="color:#686664"> |</span><span style="color:#0B0B0B;font-weight:bold"> ios</span><span style="color:#686664"> |</span><span style="color:#0B0B0B;font-weight:bold"> android</span><span style="color:#686664"> |</span><span style="color:#0B0B0B;font-weight:bold"> web</span><span style="color:#0B0B0B"> ...]</span><span style="color:#A3A09C;font-style:italic">   # or: make check, make check-ios, ...</span></span></code></pre>
<p>Always validates the contracts first and fails if generated files are out of date. Then it builds and tests each requested app and prints one line per app. Full output goes to <code>.geeknative/logs/&#x3C;platform>.log</code>; on failure, the most relevant lines are printed (up to 25). The exit code is 1 if anything failed.</p>
<div class="table-wrap"><table>
<thead>
<tr>
<th>Target</th>
<th>What runs</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>ios</code></td>
<td><code>xcodebuild test</code> for the <code>App</code> scheme on an iPhone simulator, with derived data in <code>apps/ios/.build/</code>. macOS only.</td>
</tr>
<tr>
<td><code>android</code></td>
<td><code>./gradlew :app:testDebugUnitTest :app:assembleDebug</code> in <code>apps/android</code>. Writes <code>local.properties</code> if it's missing.</td>
</tr>
<tr>
<td><code>web</code></td>
<td><code>npm run check</code> in <code>apps/web</code>: route generation and <code>tsc</code>, then Vitest, then a production build. Needs <code>npm install</code> first.</td>
</tr>
<tr>
<td><code>contracts</code></td>
<td>Only the contract validation.</td>
</tr>
</tbody>
</table></div>
<p>The simulator is the one named in <code>GEEKNATIVE_IOS_SIMULATOR</code> (a name or UDID) if set, otherwise a booted iPhone, otherwise an iPhone on the newest iOS runtime.</p>

<h2 id="parity">parity<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#parity">#</a></h2>
<pre class="shiki geeknative" style="background-color:#f5f4f2;color:#0b0b0b" tabindex="0" data-language="shell"><code><span class="line"><span style="color:#0B0B0B;font-weight:bold">npx</span><span style="color:#0B0B0B"> geeknative</span><span style="color:#0B0B0B"> parity</span><span style="color:#A3A09C;font-style:italic">   # or: make parity</span></span></code></pre>
<p>Writes <code>spec/parity.md</code> from the feature specs and the tests, and prints each feature's status and untested criteria. See <a href="/geeknative/docs/concepts/specs-and-parity/">Specs and parity</a>.</p>
