<h2 id="ios">iOS<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#ios">#</a></h2>
<p><strong>Stack:</strong> SwiftUI and Observation (<code>@Observable</code>), iOS 17 and later. Swift 6 language mode, with code isolated to the main actor by default: background work is marked <code>nonisolated</code> or <code>@concurrent</code> explicitly. Swift Testing for tests. No third-party dependencies.</p>
<p><strong>Project:</strong> <code>apps/ios/App.xcodeproj</code> uses synchronized folders for <code>App/</code> and <code>AppTests/</code>, so new files are picked up without editing <code>project.pbxproj</code>. Build settings live in <code>Config/*.xcconfig</code>:</p>

<p><strong>Patterns:</strong> a screen is <code>struct NotesScreen: View</code>; it holds its <code>@Observable final class NotesViewModel</code> in <code>@State</code>; data goes through <code>protocol NotesRepository</code>; dependencies come from <code>@Environment(AppContainer.self)</code>. Navigation is one <code>NavigationStack</code> in <code>RootView</code>: add a case to <code>Route</code> and handle it in <code>navigationDestination</code>. Each screen has a <code>#Preview</code> using <code>AppContainer.preview()</code> or in-memory repositories.</p>
<p><strong>Appearance:</strong> <code>RootView</code> applies the chosen appearance to the windows themselves, so sheets and alerts follow it too.</p>
<p><strong>Commands:</strong> <code>make check-ios</code> (build and tests on a simulator), <code>make run-ios</code>, or <code>open apps/ios/App.xcodeproj</code>.</p>
<p><strong>Gotchas:</strong> adding a Swift package changes the project file, so the agent asks you first.</p>
<h2 id="android">Android<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#android">#</a></h2>
<p><strong>Stack:</strong> Kotlin and Jetpack Compose with Material 3, Android 7.0 (API 24) and later, compiled against API 37. Navigation 3, ViewModel with StateFlow, coroutines and DataStore. AGP 9 with built-in Kotlin. JUnit and kotlinx-coroutines-test for unit tests.</p>
<p><strong>Build:</strong> every dependency version is in <code>gradle/libs.versions.toml</code>. <code>app/build.gradle.kts</code> reads the application ID and version from <code>app/identity.properties</code>, generated from <code>contracts/app.json</code>. Gradle downloads JDK 21 for the build (<code>gradle/gradle-daemon-jvm.properties</code>), so any JDK 17 or later can start it.</p>
<p><strong>Package:</strong> the Kotlin package is always <code>app</code>. The app's identity is its application ID, so renaming the app never moves code.</p>
<p><strong>Patterns:</strong> a screen is <code>@Composable fun NotesScreen(...)</code>, with a stateless content composable below it for previews. <code>NotesViewModel : ViewModel()</code> exposes <code>uiState: StateFlow&#x3C;NotesUiState></code> and action functions. Data goes through <code>interface NotesRepository</code>. Composables get dependencies from <code>LocalAppContainer.current</code>, and ViewModels are created with <code>viewModel { NotesViewModel(container.notesRepository) }</code>. Navigation is one Navigation 3 back stack: add an object to <code>Route</code>, an <code>entry&#x3C;Route.Notes></code> in <code>AppNavigation</code>, and push with <code>backStack.add(Route.Notes)</code>. Flows are collected with <code>collectAsStateWithLifecycle()</code>.</p>
<p><strong>Appearance:</strong> <code>MainActivity</code> themes the whole app from the stored appearance, waits for it to load before the first frame, and keeps the system bar icons readable.</p>
<p><strong>Commands:</strong> <code>make check-android</code> (build and unit tests), <code>make run-android</code>, or open <code>apps/android</code> in Android Studio for previews.</p>
<h2 id="web">Web<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#web">#</a></h2>
<p><strong>Stack:</strong> React 19 on TanStack Start (server rendering), with TanStack Router file routes and TanStack Query. Tailwind CSS v4 with the generated tokens, and Lucide icons. Strict TypeScript, Vite and Vitest. Supports Safari 16.4, Chrome 111 and Firefox 128 or later (Tailwind v4's minimum).</p>
<p><strong>Layout:</strong> <code>router.tsx</code> creates the router with <code>{ queryClient, container }</code> as context. Each URL is a thin file in <code>routes/</code> that renders a feature's screen; <code>routes/__root.tsx</code> is the HTML shell and the site header. Features live in <code>features/&#x3C;name>/</code>.</p>
<p><strong>Patterns:</strong> <code>NotesScreen</code> renders state from <code>useNotesViewModel()</code>, which reads data with TanStack Query and returns state and actions. Data goes through a <code>NotesRepository</code> interface. Dependencies come from router context: <code>useRouteContext({ from: '__root__' }).container</code>. Styling uses token classes (<code>bg-surface</code>, <code>p-lg</code>), not arbitrary values. For complex primitives (dialogs, menus, popovers), shadcn/ui fits: the tokens already map onto its CSS variables.</p>
<p><strong>Server rendering:</strong> code that uses browser APIs (localStorage, window) also runs safely on the server. Server functions and API routes are only for web-only concerns. The stored appearance is applied by a small script before the first paint, so there's no flash of the wrong theme.</p>
<p><strong>Commands:</strong> <code>make check-web</code> (type-check, unit tests and a production build) and <code>make run-web</code> (dev server at <code>http://localhost:3000</code>).</p>9:X
