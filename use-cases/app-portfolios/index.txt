Native quality across all of them has usually been out of reach.</p>
<p>geeknative gives every app the same structure and makes the brand a set of files, so a portfolio of native apps becomes practical.</p>
<h2 id="a-new-brand-is-a-contracts-change">A new brand is a contracts change<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#a-new-brand-is-a-contracts-change">#</a></h2>
<p>Everything that makes an app look and sound like one brand lives in <code>contracts/</code>:</p>
<div class="table-wrap"><table>
<thead>
<tr>
<th>Contract</th>
<th>Holds</th>
<th>Becomes</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>app.json</code></td>
<td>Name, bundle ID, version, default locale</td>
<td>The iOS bundle ID and Android application ID, display names and the web page title</td>
</tr>
<tr>
<td><code>tokens.json</code></td>
<td>Colors for light and dark, type, spacing, radii</td>
<td><code>AppColors</code>, <code>AppTypography</code>, <code>AppSpacing</code> and <code>AppRadius</code> on iOS, <code>AppTheme</code> mapped onto Material 3 on Android, a Tailwind theme on the web</td>
</tr>
<tr>
<td><code>strings/</code></td>
<td>Copy, with placeholders, plurals and locales</td>
<td><code>Strings</code> on iOS, string resources on Android, <code>strings</code> on the web</td>
</tr>
<tr>
<td><code>icons.json</code></td>
<td>One icon name per platform</td>
<td>SF Symbols on iOS, Material icons on Android, Lucide icons on the web</td>
</tr>
</tbody>
</table></div>
<p><code>make gen</code> compiles them into every app. An invalid contract fails with a message naming the file and field. See <a href="/geeknative/docs/reference/contracts/">Contracts</a>.</p>
<h2 id="why-it-suits-agencies">Why it suits agencies<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#why-it-suits-agencies">#</a></h2>
<ul>
<li><strong>Quote native at a competitive price.</strong> The agent writes three apps; your team reviews them. Native stops being the premium option.</li>
<li><strong>Every project looks the same inside.</strong> Same folders, same names, same commands. Anyone on the team can pick up any client.</li>
<li><strong>A clean handover.</strong> Clients get PRODUCT.md, DESIGN.md, specs with acceptance criteria and a parity report, not only code.</li>
<li><strong>No runtime to license or upgrade.</strong> The apps are plain SwiftUI, Compose and React, under your client's control.</li>
</ul>
<h2 id="why-it-suits-enterprise-portfolios">Why it suits enterprise portfolios<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#why-it-suits-enterprise-portfolios">#</a></h2>
<ul>
<li><strong>One standard for every app.</strong> Teams across business units build the same way, with the same agent instructions in AGENTS.md.</li>
<li><strong>Traceability.</strong> Acceptance criteria IDs run from the spec into each platform's test names. <code>make parity</code> writes <code>spec/parity.md</code>, a record of what is tested where.</li>
<li><strong>Accessibility through native components.</strong> VoiceOver, TalkBack and Dynamic Type work with platform components out of the box.</li>
</ul>
<h2 id="how-to-set-up-a-base">How to set up a base<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#how-to-set-up-a-base">#</a></h2>
<ol>
<li>Create a project and build your shared features once.</li>
<li>Keep that project as your base. For each brand or client, copy it and change <code>contracts/app.json</code>, <code>tokens.json</code>, <code>strings/</code> and <code>icons.json</code>.</li>
<li>Run <code>make gen</code> and <code>make check</code> to build and test the branded apps.</li>
</ol>
<p>The base is a normal geeknative project, so you can review it, version it and improve it like any other repo.</p>
<h2 id="what-to-know-first">What to know first<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#what-to-know-first">#</a></h2>
<ul>
<li>There is no built-in multi-brand build yet. Each brand is its own project, copied from your base.</li>
<li>Automated upgrades for existing projects (<code>geeknative upgrade</code>) are on the <a href="/geeknative/docs/project/roadmap/">roadmap</a>, not released.</li>
<li>There is no backend layer. Each app talks to your services through repository interfaces.</li>
</ul>
