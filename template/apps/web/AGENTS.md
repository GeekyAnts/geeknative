# Web app (React + TanStack Start)

Read the root AGENTS.md first. This file covers how the web app is built.

## Stack

- React 19 and TanStack Start (server rendering), with TanStack Router file routes and TanStack Query.
- Tailwind CSS v4 with the generated design tokens, and Lucide icons.
- TypeScript (strict), Vite, Vitest.
- Supports Safari 16.4+, Chrome 111+ and Firefox 128+ (Tailwind v4's minimum).

## Layout

```
apps/web/src/
  router.tsx              Creates the router with { queryClient, container } as context
  routes/                 One thin file per URL: head, loader, then render a feature's screen
    __root.tsx            HTML shell, site header, AppearanceEffect
  core/                   AppContainer, AppearanceEffect
    designsystem/         Shared components (AppCard, ...)
  features/<name>/        <Name>Screen.tsx, use<Name>ViewModel.ts, <Name>Repository.ts, implementations, tests
  generated/              From contracts/ by `make gen`. Never edit.
  styles.css              Tailwind entry; imports generated/tokens.css
  routeTree.gen.ts        Generated by TanStack Router. Never edit.
```

## Patterns

Same names and responsibilities as the iOS and Android apps.

| Concept | Web |
|---|---|
| Screen | `NotesScreen` in features/notes/, rendered by routes/notes.tsx |
| State and actions | `useNotesViewModel()`: reads data with TanStack Query, returns state and actions |
| Data | `NotesRepository` interface, plus implementations such as `LocalStorageNotesRepository` |
| Dependencies | `AppContainer`, in router context: `useRouteContext({ from: '__root__' }).container` |
| Navigation | A file in routes/ per screen; link with `<Link to="/notes">` |
| Copy | `strings.notesEmptyTitle` (generated) |
| Colors, spacing, radii, type | Tailwind token classes: `bg-primary`, `p-md`, `rounded-lg`, `text-title` |
| Icons | `<AppIcons.settings className="size-6" />` (generated) |
| Test IDs | `data-testid="notes.addButton"` |

Follow features/settings as the reference implementation.

## Rules

- Never hardcode user-facing text, colors or spacing. Add them to contracts/ and run `make gen`. Use token classes (`bg-surface`, `p-lg`), not arbitrary values (`bg-[#fff]`, `p-[13px]`).
- Server functions and API routes are only for web-only concerns (rendering, cookies, SEO). Logic the mobile apps need too goes through repositories, so a future backend can serve all three apps.
- Code that uses browser APIs (localStorage, window) must also run safely during server rendering.
- Use semantic HTML, give icon-only links and buttons an `aria-label` from strings, and keep focus visible.
- For complex primitives (dialogs, menus, popovers), use shadcn/ui: the tokens already map onto its CSS variables.
- Name tests after acceptance criteria: `test('AC-notes-2: ...')`.

## Commands

- `make check-web`: type-check, unit tests and a production build. Full log: .geeknative/logs/web.log.
- `make run-web`: dev server at http://localhost:3000.
